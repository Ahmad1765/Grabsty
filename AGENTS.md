# Antigravity Agent Guidelines (Grabsty)

## Mandatory UI Guardrails & Pre-Flight Protocol

Before suggesting, writing, or modifying ANY user interface, component, screen, or styling code in this repository:
1. **Read `UI_GUARDRAILS.md` first.**
2. **Perform Collision Detection:** Check whether the user's requested change conflicts with the protected rules in [UI_GUARDRAILS.md](./UI_GUARDRAILS.md).
3. **Hard-Stop on Collision:** If the request collides with protected invariants (e.g., using `className` on `<Pressable>`, breaking Inter font imports, introducing forbidden colors/gradients, removing safe-area bottom padding for the floating tab bar, or adding Depop-style badge clutter):
   - **Do NOT execute the breaking change.**
   - Warn the user about the collision and the exact risk of breakage.
   - Propose the safe, compliant alternative as specified in `UI_GUARDRAILS.md`.

## Core Technical Invariants at a Glance:
- **Never use `className` on `<Pressable>`:** Use inline `style` or `PressableScale` (NativeWind interop is unregistered via `lib/pressableInterop.ts`).
- **Never import raw `Text` from `'react-native'`:** Always use `import { Text } from '@/lib/rnText'` or `<AppText>` for Inter font mapping.
- **Strict Three-Hue Palette:** Only Signal Purple (`#6C47FF`), Paper White (`#FFFFFF`), and Ink (`#0F0F0F` / `#111111`). Approved semantic exceptions: destructive red (`#EF4444`) and canonical `<ShieldCheckIcon>` tokens (`#F2F3FE` background fill and `#5356EE` stroke). No unapproved ad-hoc colors or gradients.
- **One Primary CTA Rule:** Only one filled purple button per view.
- **Purple Button Shape:** Filled Signal Purple buttons use 10px corners (`borderRadius: 10`), never pill capsules. Chips and non-purple buttons stay pill-shaped (exception: the `Message` button on the user profile `app/user/[id].tsx` uses 10px to match `Follow`); circular icon buttons stay circular.
- **Floating Tab Bar Clearance:** Scrollable containers must include `paddingBottom` for `AnimatedTabBar.tsx` (insets.bottom + 80).
- **Unified Shield Icon Everywhere (Strict Mercari Invariant):** All buyer protection and verification marks across the app (Home cards, related items, product detail, checkout) must use canonical circular badge `<ShieldCheckIcon>` (viewBox `0 0 24 24`, circular background `#F2F3FE`, stroke `#5356EE` with canonical Mercari shield path `d="M12.033 6.8s..."` and checkmark `d="M9.4 12.013l..."` inside `<G transform="translate(-5.4, -5.4) scale(1.45)">`). Never alter these paths or substitute generic shield SVGs (`M12 3C7.5...`), teal (`#007782`), or ad-hoc shields.
- **Canonical Filter Sliders Icon (Strictly Icon-Only):** All filter controls (Home header, Discover chips, search overlays) must use `<FilterSlidersIcon>` matching the canonical 3-track horizontal sliders (top-left, middle-right, bottom-left) in a canonical 24x24 viewBox with hollow knob centers, and must be strictly **icon-only** (omit the word "Filter" / "Filters" from the visible button/chip). Never use vertical sliders or generic funnels.
- **Strictly No Cross (`×`) on Active Chips:** Never add a trailing or inline cross (`×`) icon to selected chips (Home header dynamic chips or Discover `SearchFilterChips`). Preserve symmetrical pill geometry (`paddingHorizontal: 14`); filter chips retain `chevron-down` in active text contrast.
- **Universal 30px Chip Standard:** All browse, feed, filter, topic, and refinement chips across the application (Home header `ChipRow`, Discover `SearchFilterChips`, Discover `SearchLanding` browse chips, `EditorialFeed`, `FeedFilterSheet`, profile playlists, and user filter pills) must use uniform `height: 30` with symmetrical pill geometry (`borderRadius: 15` or `radii.pill`). Circular action chips render at `width: 30, height: 30, borderRadius: 15`.
- **Discover "Saved" Chip Destination:** The "Saved" browse chip (`bookmark` icon) in Discover navigates directly to the Home feed (`/?tab=saved&chipLabel=Saved&chipIcon=bookmark`) to display saved listings directly on the main feed grid, never to `/news`.
- **Cross-Platform Keyboard Docking & Safari Viewport:** Never use naive binary padding toggles (e.g. `keyboardUp ? 6 : insets.bottom`) which cause visual snapping. Animate composer dock padding smoothly using `Animated.Value` (`keyboardAnim`) synced with native keyboard show/hide event durations. In `KeyboardAvoidingView` / `<SafeContainer mode="keyboard-avoiding">`, use `behavior="padding"` on iOS and Android (edge-to-edge disables `adjustResize`), with `enabled={useAndroidKeyboardShown()}` so no stale padding remains after the keyboard hides. In chat lists, anchor with `onLayout` and avoid unconditional `justifyContent: 'flex-end'` on long lists. On mobile web, always sync with `visualViewport.offsetTop` and `visualViewport.height`.
- **Canonical Sharp Sold Badge (Strict Plick Invariant):** All sold status indicators across the application (Home feed `ListingCard`, profile shop/liked grids `TikTokListingCard`, and product detail hero overlays `ProductHeroSection`) must use `<SoldBadge>` from `@/components/ui/SoldBadge` with **strictly sharp rectangular corners (`borderRadius: 0`)** across all sizes (`sm`, `md`, `lg`), Signal Purple background (`#6C47FF`), Paper White bold Inter text, and subtle elevation shadow. Never round the corners (`borderRadius > 0`), convert to pill badges, or introduce ad-hoc inline sold containers.
- **Strict Monochrome 10px Product Action Bar Invariant:** The bottom action buttons in `components/product/ProductActionBar.tsx` (`Make an offer` and `Buy now`) are strictly locked: `height: 48`, **strictly 10px rounded corners (`borderRadius: 10`)**, and monochrome palette. "Make an offer" must use Paper White (`theme.panel`) with hairline border and Ink text (`theme.ink`). "Buy now" must use Solid Ink (`theme.ink`) with white text (`theme.background`). Never convert these buttons to pill capsules (`radii.pill` or `borderRadius: 9999`), never color "Buy now" with Signal Purple (`theme.purple`), and never alter their button geometry or monochrome styling.
- **Strict Activity Screen & Purchases/Selling Invariant:** Activity top tabs in `app/(tabs)/chat.tsx` are strictly locked to three: `Orders`, `Messages`, and `Support`. Never extract sales to a separate top tab and never remove selling. `OrdersInboxPage.tsx` must maintain the segmented sub-toggle between `Purchases` and `Selling` directly above the 36px Whatnot squircle filter chips (`borderRadius: 8`, labels: `All`, `In Progress`, `Completed`, `Refunds`, `Canceled`), preserving quick shop listing actions (`+ New item`, `View shop`) in the Selling view, Whatnot order row layouts (72x72 square thumbnail, top status pills, bold title, price, date, counterparty, hairline divider), and no message row dividers.
- **Strict React Native `testID` Standard:** Never use HTML `data-testid` on React Native components (`<TextInput>`, `<Pressable>`, `<View>`, `<PressableScale>`). Always use `testID="..."`. React Native for Web automatically compiles `testID` to `data-testid` in the DOM for Playwright (`page.getByTestId(...)`).
- **Never bypass `GuestGate`:** Maintain auth guards on offer, purchase, sell, and chat actions.
